## 1. Résumé

- Aucun contournement du scope au niveau du gate. Aucun chemin vers le jeton OAuth, les mots de passe ou le jeton Gmail.
- Le relais Anthropic ne lit pas le corps des requêtes. Un chasseur compromis peut y demander des outils côté serveur (H1, supposé).
- L'étage A du juge se fabrique : la preuve « navigateur » est satisfaite par l'URL que `bh-browse` recopie (H2, prouvé).
- Un 403 normal derrière Cloudflare compte comme un challenge WAF. Trois suffisent pour 1 h de pause (H3, prouvé).
- Un seul 401 sous identité marque la session morte. La doc dit « répétés » et « 3 × 401 » (H4, prouvé).
- Un finding rejoué pendant une pause WAF finit `inconclusive` définitif, après Opus puis Mythos. La doc promet un réessai (M1).
- Un fichier du sandbox mal formé fait tomber toute la chasse, à chaque relance (M4, prouvé).
- Entre deux legs d'un segment rien n'est nettoyé. Le prompt système vit dans un dossier que le chasseur écrit (M5).
- Le juge est bien isolé (conteneur, nonce, remise à zéro). C'est la partie la plus solide de ce diff.

## 4. Ce qui est solide (essayé, pas cassé)

- **Jeton OAuth.** Présent dans le gate seul (`compose.yaml:58`). Le relais fixe l'hôte amont et le `Host` (`addon.py:361`), n'accepte que deux couples méthode-chemin exacts (`:64`, `:345`), refuse hors run. Le CONNECT direct vers l'API est refusé (`policy.py:175`).
- **Pair du relais.** Jugé sur l'IP résolue de `agent` et `judge`. Sans `NET_RAW` ni `NET_ADMIN`, pas d'usurpation. Le proxy chaîné sur lui-même arrive avec l'IP du gate : refusé.
- **Scope.** Scopes de lab en `/32` : l'IP du gate n'y est pas. IP non publique seulement par CIDR explicite (`enforce.py:117-129`). URL de login, d'inscription et de sonde contrôlées au chargement du scope.
- **Enrôlement.** Mot de passe sur stdin seul (`enroll.py:168`), `python3 -I`, pas de suivi de redirection. Erreurs réduites à un type et un statut, mot de passe effacé (`:286`). Recette sans secret littéral ni variable dans une URL (`recipe.py:77`, `:90`). Secrets en 0600, jamais montés.
- **`X-BH-Gate`.** Retiré des réponses de cible (`addon.py:505`) : une cible ne simule pas un refus du gate.
- **Jarre de cookies.** `Domain` étranger et suffixe public refusés, tailles bornées, écriture atomique sous verrou. `Set-Cookie` masqué avant toute écriture ; le navigateur renvoie le masque, le gate remet la vraie valeur.
- **Nom d'identité.** Regex stricte, pas de traversée (`addon.py:428`). L'en-tête est retiré avant l'amont.
- **Juge.** Conteneur, `/work`, utilisateur et HOME propres. Tout est tué puis recréé avant chaque juge et avant l'escalade (`stack.py:142-149`). Nonce par process, verdict lu dans `var/judge` seul. Aucun port en écoute : le chasseur n'a rien à joindre.
- **Notes.** Rotation par run et par leg. Lecture par lien symbolique relatif vers `secrets/` ou `var/state` essayée : seules les lignes avec `op` sont lues, rien ne revient à l'agent.
- **Session de l'agent.** `--tools Bash,Read`, `--strict-mcp-config`, pas de sous-agent ni d'outil web client. Code monté en lecture seule.
- **UI.** Session HMAC, `SameSite=Strict`, en-tête `X-BH` sur les POST, CSP stricte, chemins bornés. Aucun secret d'identité servi.
- **Labs.** Pas de port publié, code en lecture seule. Leur accès au proxy est une limite connue ; le relais leur reste fermé.
